# Preview Penggajian

Alur Kelola: daftar/filter → rincian → pengaturan empat metode → catat pembayaran → riwayat/slip. Implementasi memakai Card, Form, Wrapper, SingleSelect, CatalogItemCard, DetailRow, modal, dan BottomActionButton bersama. Header berada di nested layout. Ditinjau pada 8 Oktober 2026 (Asia/Jakarta) dengan dependency Expo SDK57.

Pengaturan mendukung Bulanan (gaji pokok/tunjangan/makan/transport), Harian (hari × tarif), Per Jam (jam × tarif), dan Per Layanan (jumlah tiap layanan × komisi). Tarif harian/jam direset ketika metode berubah agar pengguna memasukkan tarif dengan satuan yang benar. Total dihitung dari record; contoh 12 × Rp25.000 + 20 × Rp15.000 + 30 × Rp10.000 + 15 × Rp40.000 menghasilkan 77 layanan dan Rp1.500.000. Angka total Figma yang berbeda dari rincian tidak disalin.

Daftar memakai periode yang dipilih, pencarian nama/peran/metode yang di-trim, status Belum Dibayar/Sebagian/Lunas, reset, dan total hasil filter. Ringkasan tiap status menjumlahkan penghasilan bersih record dalam status tersebut. Jumlah dibayar dan sisa ditampilkan pada detail/riwayat/slip. Empat record Oktober 2026 memiliki total penghasilan bersih Rp24.400.000; record September/Agustus tidak tercampur dalam periode Oktober.

Form memvalidasi kalender ISO 1900–2100, Rupiah bulat hingga Rp1 triliun, batas panjang teks, tarif positif sesuai metode, serta komisi layanan yang dikenal/tidak ganda. Pengaturan tidak mengubah aktivitas atau record lain, dan draft tetap ada ketika record lain berubah. Pengaturan tidak dapat diubah setelah pembayaran pertama agar rincian periode yang sudah dibayar tetap konsisten.

Callback input angka hanya pada Payroll mempertahankan nilai pecahan/negatif saat ditempel agar schema menolaknya; tidak menghapus tanda lalu menyimpan nominal berbeda. Saat metode berubah, nilai tidak valid pada komponen yang disembunyikan dipulihkan dari record, sedangkan draft komponen valid tetap dipertahankan. Primitive FormInput bersama tidak diubah.

Pembayaran penuh memakai sisa tepat; sebagian harus positif dan tidak melebihi sisa. Bonus/potongan/kasbon menentukan penghasilan bersih dan dikunci setelah pembayaran pertama. Referensi wajib dan unik di seluruh record, transfer memerlukan rekening tujuan, tanggal pembayaran tidak boleh mendahului periode, dan ID hilang/periode lunas ditolak. Simpan pertama memakai ID pembayaran yang sama untuk percobaan berikutnya; form menjadi terkunci dengan CTA Lihat Slip Gaji. ID pada timestamp yang sama memperoleh suffix berbeda. Semua status/rincian/riwayat/slip membaca record store yang sama.

Unduhan web berupa HTML UTF-8, memakai teks yang di-escape, dapat dibuka dan dicetak melalui browser. Native membagikan ringkasan teks dengan Share. Ekspor memuat metode, rincian, penyesuaian, penghasilan bersih, total dibayar, sisa, dan metadata setiap pembayaran. Data contoh dan slip diberi penanda pratinjau; pencatatan ini tidak mengirim uang atau menjadi bukti transfer nyata.

Feature memakai fixture payroll tersendiri berdasarkan metadata desain karena frontend belum memiliki kontrak API penggajian. Data ini tidak mengganti API/auth/mode aplikasi global dan tidak memutasi accountingStore. State hanya selama proses aplikasi; belum persistensi/API, data karyawan/absensi/layanan nyata, pajak/prorata, atau jurnal/saldo otomatis. Nama/store/aktivitas dalam screenshot adalah contoh, bukan data akun yang sedang login. Tanggal memakai input ISO karena DateTimePicker bersama belum memiliki implementasi web/iOS; primitive bersama tidak diubah.

Verifikasi: [39 pemeriksaan model/schema](model-results.json) dan [29 pemeriksaan browser](results.json) lolos, tanpa runtime exception atau console error. TypeScript seluruh proyek exit 0; ESLint/Biome 18 file sumber Payroll bersih. Model mencakup empat metode, total/status/filter, kalender, batas nominal/teks/komisi, penyimpanan terisolasi, penjagaan periode sudah dibayar, pembayaran penuh/sebagian, referensi ganda, penguncian penyesuaian, simpan berulang, ID pada timestamp sama, HTML escape, dan isolasi accountingStore.

Browser memeriksa pencarian/filter/reset/total, pergantian keempat metode, tarif yang harus diisi ulang sesuai satuan, prefill, draft saat record lain berubah, tempelan angka pecahan/negatif/di atas batas, pemulihan field tidak valid yang disembunyikan, kalender, simpan berulang, transfer/referensi ganda, pembayaran sebagian hingga lunas, penguncian pengaturan/penyesuaian/form, ekspor HTML, riwayat per karyawan, ID hilang/periode lunas, koleksi kosong, dan keenam layar pada 320 px. CTA diuji dengan trial click dan pemeriksaan elemen di titik tengah tombol. Geometri tombol kembali Header SDK57 juga lolos setelah perbaikan cssInterop oleh sesi migrasi; primitive tersebut tidak diubah oleh Payroll.

Harness web lokal memakai komponen produksi, parameter route, providers/fonts, dan stack sederhana. Pembukaan root berikutnya mengganti parameter/stack serta mereset salinan fixture, dengan provider/font tetap berada dalam satu halaman. Bundle pertama membutuhkan sekitar 399 detik pada komputer ini; percobaan reload berulang juga tertunda sebelum layar tampil. Hasil akhir memakai harness satu halaman setelah pemuatan awal, tanpa mengubah aplikasi. Screenshot sempit diposisikan kembali ke bagian atas untuk menghindari posisi scroll dari interaksi sebelumnya.

Navigator/auth penuh serta fitur pada perangkat native belum diverifikasi. Ini belum mengklaim verifikasi Share native atau tampilan seluruh navigator produksi. Screenshot memakai fixture yang berubah selama alur pembayaran; indikator dev Expo dapat terlihat pada bundle development. Edge tes memakai flag LocalNetworkAccessChecks untuk websocket localhost; flag hanya berlaku pada proses tes. Skrip berada di `.expo` sebagai artefak lokal:

Server sementara 8096 dihentikan setelah verifikasi dan port diperiksa tidak listening; gambar percobaan gagal dibersihkan. Server sesi lain tidak dihentikan atau diubah.
