# SD3-013 — Metode Pembayaran sesi aplikasi

Owner: Software Developer Senior / Codex-3. Status: READY_FOR_QA_QC; bukan approval QC atau publikasi.

Daftar Kelola sebelumnya memakai tipe pesanan (Dine-In, Take Away, Delivery, Pre-Order), sedangkan form mengedit satu fixture Transfer Bank. Hapus hanya membuka dialog berhasil tanpa menghapus record. Flow sekarang memakai daftar kosong awal yang diisi pengguna: tambah, daftar/pencarian, detail read-only, edit berdasarkan ID stabil, dan hapus yang benar-benar menghapus record sesi sebelum menampilkan sukses.

Seluruh tujuh field dipertahankan: nama, jenis transfer bank, tipe biaya admin, nilai biaya, bank, nomor rekening, dan pemilik rekening. Store tidak memakai seed fixture, persist middleware, storage, atau API. Data tersedia selama aplikasi terbuka; belum terhubung ke transaksi. Nilai biaya admin ditampilkan sebagai metadata, tidak menghitung atau menerapkan biaya pada Kasir. Bank `bca`/`bni`/`bri`/`mandiri` tetap nilai UI, bukan ID bank backend.

Nama/pemilik/nomor rekening dinormalisasi dengan trim; bank dinormalisasi lowercase dan pilihan divalidasi. Biaya harus finite, nonnegative, maksimal 100 untuk persentase; nominal dapat lebih besar. Default 0 ditampilkan sebagai `0`, dan mengosongkan input menghasilkan nilai invalid. Input biaya memakai override `fieldProps` pada shared FormInput agar tanda minus/desimal tidak dibuang oleh parser number shared; `-1` tetap negatif, `1,5` menjadi 1.5, nomor rekening mempertahankan leading zero. Pilihan pembayaran masih Transfer Bank sesuai opsi existing.

Route index/modify/detail memakai komposisi owned di settings. Header Detail Metode Pembayaran ditambahkan pada layout existing. Modify snapshot draft per ID/create; refetch/perubahan record dengan ID sama tidak menimpa input, berganti ID/reset create membuat lifetime baru, unknown/empty ID menampilkan kembali-ke-daftar. RHF submit setelah unmount, duplicate submit dan duplicate acknowledgement ditolak. List memakai ManageListActions generation/canonical selection yang sudah diserahkan SD3-011. Detail menggunakan Content keyed ID. Child delete dipertahankan saat record hilang agar notice sukses masih dapat ditutup; cancel/stale callback tidak menghapus data. Tidak mengubah hub Kelola, tiga preview lain, ManagePreviewForm, shared UI, Catalog, API hooks/DTO, fixture constants, backend atau dependency.
